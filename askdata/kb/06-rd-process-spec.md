# 研发流程规范

## 需求阶段
需求由产品经理统一收集，形成需求文档（PRD），经评审通过后进入排期。需求变更须走变更评审，评估对工期的影响。

## 开发阶段
采用 Git 分支管理，主干为 main，功能开发在 feature 分支进行。每人每天至少提交一次代码，提交信息须说明变更目的。

## 测试阶段
单元测试覆盖率要求不低于 70%。所有 PR 必须经过至少一名同事评审才能合并。测试环境与生产环境严格隔离。

## 发布阶段
每两周一个发布窗口。发布前须完成回归测试，发布后观察 24 小时。重大版本采用灰度发布，先对 5% 流量开放。

## 事故复盘
线上事故须在 3 个工作日内完成复盘，输出复盘报告，明确根因、影响范围与改进措施，避免同类问题重复发生。
