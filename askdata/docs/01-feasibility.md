# 赛题八 可行性评估与得分预估

> 评估对象：中国电子杯第三届高校 ICT 产教融合创新大赛 赛题八
> 多模态数据驱动的可解释精准问数/问答智能体（中电云计算）
> 评估日期：2026-09-28　评估依据：赛题原文 + 已跑通的 Demo 实测数据

## 一、结论先行

| 结论 | 说明 |
|---|---|
| **值得报** | 门槛低、上限高。基础 25 分只需"能跑通"，中级任务可选做，允许只交 1 个 |
| **最小可行目标** | 校内初赛 60~75 分（基础分拿满 + 攻克 1~3 个中级任务） |
| **冲刺目标** | 决赛 85 分以上（跨源融合 + 澄清交互 + Schema Linking 三个硬骨头） |
| **最大风险** | 不是技术难度，而是**文档工作量**（设计报告 20 页 + 说明书 30 页）与**中级任务深度** |

## 二、为什么值得报

### 1. 硬门槛很低
赛题明确：**至少完成 1 个中级任务**即为有效参赛作品。9 个中级任务里，
"③语义校验与澄清"这类任务本质上是一段**规则 + 一次 LLM 判断**，不需要训练模型。

### 2. 分值结构对"认真做"友好

| 分值块 | 分 | 拿分难度 | 说明 |
|---|---|---|---|
| 基础 NL2SQL 单表 + RAG 单文档 | 20 | **低** | ≥10 用例即可，我已跑通 12/12 |
| 可解释性 + Demo 可用性 | 10 | **低** | 展示 SQL / 片段 / 链路即可 |
| NL2SQL 准确率 ≥90% | 10 | **中** | 单表+多表聚合，实测已 100% |
| RAG 忠实度 ≥90% | 10 | **中** | 关键在"只依据资料回答"，可约束 |
| 系统效率分析 | 5 | **低** | 写复杂度分析 + 两种规模实测 |
| 中级任务（≥1 个，5分/个） | 15 | **中** | 建议挑 3 个 |
| 鲁棒性 | 10 | **中** | SQL 报错自动修正 + 模糊输入容错 |
| 多轮上下文 | 5 | **中** | 5 轮以上准确 |
| 技术文档 | 10 | **中** | 需投入时间写作 |
| 演示效果 | 5 | **低** | 录屏即可 |

**合计可争取 100 分**，其中"低难度"部分已有 40 分。

### 3. 题目已把资源喂到嘴边
- 数据集直接指定：OHR-Bench（本体）、Chinook（数据库）、AdventureWorks（复杂）
- 数据库有现成 SQLite 文件，AdventureWorks 有 Docker 镜像
- 开发环境建议 Python + Vue，不限定框架

## 三、已完成的实测证据（非预估）

### 1. NL2SQL 执行准确率

在 Chinook（11 张表、3503 首曲目、412 张发票）上跑 12 题，覆盖单表计数、聚合排序、多表关联、条件筛选、分组求最：

```
=> 12/12 = 100.0%
```

### 2. 跨源融合（本题最难的考察点）
问题："2024年销售冠军是谁？请结合知识库总结他的成功方法论。"

系统自主规划为 hybrid 路线，实际执行链：
```
① 意图路由：需先查库定冠军，再查知识库方法论
② NL2SQL：JOIN Employee/Customer/Invoice，按 2024 年分组求和 → Margaret Park, 197.2
③ 用查得的实体构造检索词 → 命中「03-销售冠军方法论」相关度 15.95
④ 融合生成：结论 + 三步破冰法 + 依据标注
```
**答案正确，来源可核对。** 这是评分表中"应对复杂多跳问题得 10 分"的对应能力。

### 3. 可解释性
每次问答固定产出四类证据：推理链步骤、生成的 SQL 原文、SQL 结果表、命中片段（含相关度与关键词）。

## 四、真正的难点与对策

| 难点 | 赛题原话 | 对策 | 风险 |
|---|---|---|---|
| Schema Linking | 数十张表中精准定位 | BM25 + 取值匹配做表/列召回，只把候选 schema 给模型 | 中 |
| 模糊输入澄清 | 主动发起澄清 | 路由阶段检测缺失维度，返回澄清话术 | 低 |
| 文档公式识别 | 识别公式参数与结构 | 最难的中级任务，建议**不选** | 高 |
| 乱目录层级 | 目录层级丢失 | 需 PDF 解析 + 层级还原，中高难度 | 中高 |
| 多模态（含图/扫描件） | 模糊扫描件、颠倒图片 | 需 OCR + 图像处理，工程量大 | 高 |
| 文档工作量 | 20 页 + 30 页 | 从现在开始边做边记，别最后补 | **最容易翻车** |

## 五、建议的中级任务取舍

**优先攻克（性价比高）：**
1. **③ 智能语义校验与澄清** — 规则 + LLM 判断，1~2 天可成
2. **④ 精准 Schema Linking** — BM25 召回表/列，可量化（候选表减少比例、准确率）
3. **① 要素识别与问题改写** — 别名词典 + 改写，可演示"帝都→北京"

**慎选：** ⑥文档公式识别、⑦乱目录、⑨文档质量评估（OCR/图像方向，工程量陡增）

**可作加分项：** ⑧ 文档复杂度评估（设计评分规则，容易写成一篇像样的方法论）

## 六、时间估算（按每周投入 10 小时）

| 阶段 | 内容 | 预估 |
|---|---|---|
| 第 1 周 | 跑通 Demo、确定中级任务 | 已基本完成 |
| 第 2~3 周 | 攻克 2~3 个中级任务 + 鲁棒性 | 20~30 h |
| 第 4 周 | 测试集扩充、准确率调优、效率实测 | 10 h |
| 第 5 周 | 设计报告 + 技术说明书 + 录制演示 | 15~20 h |
| 第 6 周 | 打磨、检查提交物 | 5 h |

**总计约 60~75 小时。** 若时间不足，可只保基础 4 项 + 1 个中级任务，约 25 小时即可交出一份有效作品。

## 七、明确的限制（不夸大）

- 当前知识库为 12 份**演示文档**（与 Chinook 同源），**尚未接入 OHR-Bench 等公开真实文档集**
- 检索为 **BM25 关键词检索**，同义改写的召回弱于向量检索
- 未做 OCR、未处理扫描件/图片，第 ⑨ 类中级任务未涉及
- 多轮对话仅保留最近 5 轮，仅用于指代消解
- 上述准确率是**在自有小测试集上**的结果，不代表在赛题官方测试集上的表现
